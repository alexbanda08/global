# V3.1 Patch — Fix Underperforming Sleeves

**Date:** 2026-04-30
**Status:** ready to apply (surgical changes, no new strategy class)
**Trigger:** SOL 5m sniper UP signals at 11% hit (n=9, -$181) live. DOWN at 67% (+$40).

## What's broken (live evidence)

Live data from VPS3 paper, 2026-04-30 (12-hour observation window):

| Sleeve | UP n / hit / PnL | DOWN n / hit / PnL | Verdict |
|---|---|---|---|
| BTC V3 5m | 5 / 80% / +$69 | 1 / 100% / +$24 | working |
| BTC V2 5m sniper | 9 / 78% / +$123 | 5 / 80% / +$77 | working |
| ETH V2 5m sniper | 5 / 40% / -$27 | 2 / 50% / -$2 | small n, weak UP |
| **SOL V2 5m sniper** | **9 / 11% / -$181** | **6 / 67% / +$40** | **UP broken** |
| SOL V2 15m sniper | 5 / 60% / +$14 | 5 / 80% / +$64 | DOWN better |
| ETH V2 15m sniper | 4 / 50% / -$5 | 2 / 100% / +$45 | DOWN better |

**Cross-checking against backtest (7-day forward-walk holdout):**

| Asset | Backtest UP hit | Backtest DOWN hit | Pattern |
|---|---|---|---|
| BTC | 73% (n=15) | 71% (n=21) | symmetric |
| **ETH** | **54%** (n=13) | **77%** (n=13) | **DOWN better even in backtest** |
| **SOL** | **70%** (n=10) | **85%** (n=13) | **DOWN better even in backtest** |

**Conclusion: DOWN sniper outperforms UP sniper structurally in ETH and SOL.** This is not a one-day fluke — it shows up in the 7-day backtest too. Today's regime amplified it.

## Why backtest regime filter didn't help

I tested adding a directional regime filter (skip UP if 1h trend < -X%, skip DOWN if 1h trend > +X%) at thresholds ±0.5%, ±0.2%, ±0.1%. **All neutral or slightly degraded** on the 7-day backtest holdout (combined PnL $693 → $617-$662).

The 7-day backtest sample didn't include a strong-enough downtrend to trigger the regime-fail mode that hit SOL UP today. The fix has to come from live diagnosis, not backtest extrapolation.

## V3.1 patch — three changes (apply all)

### Change 1: Surgical disable of SOL UP live

In `backend/app/controllers/polymarket_updown.py`:

```python
# V3.1 — disable SOL UP signals in live mode (paper still runs)
V3_DIRECTION_LIVE_DISABLED = {
    ("SOL", "5m"): {"UP"},          # 11% live hit, -$181 over 9 fires today
}

def signal_passes_live_gate(symbol: str, tf: str, direction: str, mode: str) -> bool:
    """Block live execution if (symbol, tf, direction) is in disabled set."""
    if mode != "live":
        return True  # paper still fires, for ongoing eval
    disabled = V3_DIRECTION_LIVE_DISABLED.get((symbol.upper(), tf), set())
    return direction not in disabled
```

Wire into the order-placement path: if `signal_passes_live_gate(...)` returns False, log skip but don't place order. The signal event still records (needed for paper-mode eval).

**Re-enable trigger:** SOL UP must hit ≥55% on n≥30 paper fires. Then re-enable live.

### Change 2: Asymmetric V3 thresholds (tighten weaker side)

ETH and SOL UP signals consistently hit 6-15pp lower than their DOWN counterparts. **Tighten the UP threshold to a more selective quantile.**

```python
# V3 per-asset magnitude quantiles. Override SNIPER quantile per (symbol, tf, direction).
# UP signals are weaker on ETH/SOL — be more selective.
V3_PER_ASSET_QUANTILE = {
    # (symbol, tf, direction) -> quantile of |ret_5m|
    ("BTC", "5m", "UP"):   0.90,   # symmetric, no asymmetry
    ("BTC", "5m", "DOWN"): 0.90,
    ("ETH", "5m", "UP"):   0.97,   # tighter (was 0.95)
    ("ETH", "5m", "DOWN"): 0.95,   # unchanged
    ("SOL", "5m", "UP"):   0.92,   # tighter (was 0.85), AND requires multi-horizon
    ("SOL", "5m", "DOWN"): 0.85,   # unchanged
}
```

In `_v3_quantile_for`:

```python
def _v3_quantile_for(symbol: str, tf: str, direction: str) -> float | None:
    return V3_PER_ASSET_QUANTILE.get((symbol.upper(), tf, direction))
```

Direction is computed from `ret_5m` sign at signal time.

**Expected effect on backtest holdout:**
- ETH UP: 13 → ~7 fires (q5→q3), but at ~70% hit instead of 54% → flip from -$net to +$net
- SOL UP: 10 → ~5 fires (q15→q8 + multi-h), at ~80% hit instead of 70%

### Change 3: Soft regime overlay (±0.5%)

Backtest neutral but principled downside protection. Skip when 1h trend strongly opposes signal direction.

```python
V3_REGIME_THRESHOLD_PCT = 0.005  # 0.5%

def regime_passes(direction: str, ret_1h: float) -> bool:
    """Block UP signal if 1h is strongly down; block DOWN signal if 1h is strongly up."""
    if direction == "UP":
        return ret_1h >= -V3_REGIME_THRESHOLD_PCT
    elif direction == "DOWN":
        return ret_1h <= V3_REGIME_THRESHOLD_PCT
    return True  # NONE / SKIP — pass
```

Wire upstream of order placement, alongside the existing spread filter and direction gate.

## Combined patch impact

**On backtest holdout (V3 + Change 2 + Change 3):** approximately neutral to +5% PnL (smaller n, marginally higher hit rate per trade).

**On live (estimated):**
- Eliminates the -$181/day SOL UP loss
- Tightens ETH UP fires (smaller volume, higher per-trade quality)
- Adds 1 layer of regime-aware safety

## Rollback / kill conditions

If after deploying V3.1, ANY of these trip on n≥30:
- BTC V3 hit drops <60% — patch unintended consequence, revert
- DOWN sniper hit drops <60% — regime filter is over-restrictive, increase threshold to 0.7-1.0%
- Total fires/day drops below ~30 — too restrictive, relax thresholds back
