## Phase 36 implementation history (what's been shipped)

### 2026-05-26 session — Bug 1 fix deployed

**Root cause**: Phase 35/36 BarContext builders did `feed = getattr(primary, "feed", None) or getattr(primary, "_feed", None)` but the controller never exposed `feed` as an attribute. The feed is bound globally via `bars.set_feed_instance()` at engine boot.

**Fix**: New `get_feed_instance()` accessor in `backend/app/data/bars.py`. All 3 `build_bar_context_*` read sites in `backend/app/engine/poly_updown_loop.py` updated. Commits `c6bee19` + `8a27677`.

**Verification**: First Phase 1 Kelly `order_placed` at 14:13 CEST after fix. Pre-fix: 0 fires across all Phase 36 sleeves in 26 h. Post-fix: 6 `order_placed` events in first 10 min.

### Other bugs fixed same session

- **Bug A (deque clear on reconnect)** — `backfill_from_rest` was clearing the 14d deque on every WS reconnect, shrinking it to 1440 bars and biasing the q90 threshold 22% low for hours. Fix: new `gap_fill=True` mode walks forward from deque tail without clearing. Commits `c6bee19` + `8a27677`.
- **Bug B (poly redeemer unbounded pool)** — losers never DB-marked, pending pool grew to 79 stale losers blocking 4 newer winners. Fix: new `_INSERT_LOSER_SKIPPED_SQL` writes `kind='poly_redeemer_skipped'` event on loser scan. Commit `fb50401`. 4 winners redeemed at 15:03 UTC.
- **Bug C (Ireland import crash)** — `Vwap15mStore` import unconditional in `binance_market_data.py` broke Ireland deploy (no Phase 35 deploy). Fix: optional import. Commit `c6bee19`.
