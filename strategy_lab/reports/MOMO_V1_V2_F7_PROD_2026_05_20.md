# Momo v1 / v2 production strategies — F7 filter overlay

_2026-05-20. Production momo v1 and momo v2 sleeves run as-is on canonical
data, with F7 RSI(14) overlay. No new architecture, no late-fire variants —
just the existing strategies measured against 26d of canonical data with
both legacy and real Polymarket fee accounting._

## Setup

- **Strategies**: production-as-deployed
  - **momo v1**:
    - 5m: anchor `ret(ws-300, ws-180)`, fire at `ws-180`
    - 15m: anchor `ret(ws-900, ws-780)`, fire at `ws-780`
  - **momo v2**:
    - 5m: anchor `ret(ws-360, ws-240)`, fire at `ws-240`
    - 15m: anchor `ret(ws-960, ws-840)`, fire at `ws-840`
- **Gate**: |ret_2m| ≥ q90 from rolling 14d per (asset, tf, day)
- **Signal**: UP if ret_2m > 0 else DOWN; fill at best-ask of that side
- **F7 filter**: RSI(14) on binance 1m at fire time
  - F7: UP needs RSI > 50, DOWN needs RSI < 50
  - F7x: UP needs RSI > 60, DOWN needs RSI < 40
- **Engine**: `engine_v2.LegacyConfig` (matches production shadow accounting:
  no latency shift, no min_book_events filter, legacy 2%-on-profit fee, strict-asof
  book lookup, spread filter 2¢ BTC/ETH / 2.5¢ SOL)
- **Real-fee column**: per-trade post-process using `fee = 0.07 × p × (1-p) × shares`
  charged on every fill (winning + losing legs) — matches `cyclops/_results/_real_fees_rerun.py`
- **Universe**: chainlink-resolved markets, BTC/ETH/SOL × 5m/15m, 2026-04-24 → 2026-05-19 (26d)
- **Notional**: $25/trade

**Aggregate F7 effect**:
- Baseline_v1: legacy −$2,500 → F7 −$2,201 (Δ +$299, +$11.5/day extrap)
- Baseline_v2: legacy −$2,149 → F7 −$2,037 (Δ +$112, +$4.3/day extrap)

likely the REST-staleness leak in production fills (book is $0.19-0.32 stale at fire
time, giving favorable entries that don't survive a strict-asof backtest).

## Three observations

### 1. F7 effect is real but **not universal**

F7 helps in 9/12 cells. The 3 cells where F7 **hurts** are:
- **Baseline_v1 btc_15m**: −$127 (still profitable, just less so). The Baseline_v1 BTC 15m
  signal is strong enough that the RSI filter cuts genuine winners.
- **Baseline_v2 btc_5m**: −$195. F7 cuts ~25% of fires but the survivors lose more per trade.
- **Baseline_v2 sol_5m**: −$30 (marginal).

### 2. Production v1 BTC 15m is the only universally-profitable cell

Profitable cells across (variant × F7) combinations:
- Baseline_v1 btc_15m: ALL +$381, F7 +$254, F7x +$148  (all positive)
- Baseline_v2 btc_15m + F7: +$265 (F7 flips it from −$47 to +$265)

**Everywhere else is negative** after real Polymarket fees. The strategy edge is
concentrated entirely on **BTC 15m**.

### 3. F7 hurts WR sometimes but helps PnL — and vice versa

Counter-intuitive cases:
- **Baseline_v1 sol_15m**: WR jumps 42.9% → 48.3% (+5pp) with F7, but n drops 35→29.
  Small-sample, but real-PnL improves +$107.
- **Baseline_v2 btc_15m**: WR jumps 51.8% → 55.6% (+4pp) with F7. PnL flips negative
  to positive (+$313 Δ).
- **Baseline_v2 sol_15m**: WR jumps 42.5% → 45.3% with F7. PnL improves +$226.

So F7's value comes from **WR pick-and-reject**, not just trade-count reduction.

## Recommendations

1. **Deploy production strategies on BTC 15m only**:
   - Baseline_v1 ALL: real $+381, $+2.91/trade — top option (don't apply F7 here)
   - Baseline_v2 F7: real $+265, $+1.76/trade — second option

2. **Drop all 5m cells**. Universally negative across both variants after real fees.

3. **Drop ETH/SOL 15m**. Even with F7 lift, both stay negative for production strategies.

4. **F7 default = ON for BTC 5m and SOL 15m** (where it helps materially)
   **F7 default = OFF for BTC 15m** (where it cuts genuine winners on v1)
   This contradicts production's "blanket F7 ON" deployment. Worth A/B testing
   per-cell F7 enable in production.

5. **The +$3.6k/day production F7 lift number is suspicious**. Live-mimic backtest
   shows only ~$11.5/day aggregate F7 lift on Baseline_v1 (Δ legacy = +$299 / 26d).
   Investigate REST-staleness contribution to production paper PnL before deploying
   beyond BTC 15m.
