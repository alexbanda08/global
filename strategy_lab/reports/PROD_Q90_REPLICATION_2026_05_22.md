# Production q90 replication - chainlink vs feed-backed (2026-05-22 06:00 UTC)

Replicates production's `_fetch_abs_ret_2m_history` calibration (feed-backed deque, every 1MIN bar, rolling 14d) and compares to the chainlink-only q90 used in `momo_variants_2abc.py`.

## Method

- For each asset, compute |ret_2m| = |log(close@t / close@(t-120s))| on every binance-spot-ws 1MIN bar.
- Prod-q90: hourly rolling 14d q90 over ALL bars - emulates the production deque sampled at each fire decision.
- Chainlink-q90: rolling 14d q90 sampled ONLY at slug-aligned timestamps per (asset, tf) - emulates `momo_variants_2abc.py`.
- Fire-count proxy: count slug timestamps where |ret_2m| >= threshold.

## Interpretation

- If `prod q90 < chainlink q90`, the production calibration is LOOSER than ours and would fire MORE often - this is the expected direction per the handoff.
- The `fire_ratio_prod_over_chainlink` column tells you exactly how many more fires you'd see if you swapped the threshold.
- The actual production fire rate also depends on the universe (production includes binance-resolved markets we drop). The ratio here measures the ISOLATED effect of the threshold calibration.
