**Date:** 2026-05-31  |  **Cost model:** Realistic (poly_taker_curve 0.07·p·(1-p) + $0.01 tx per trade)

## Overview

Tests whether the live `poly_sniper_v5_btc_15m_ema50_ema800_off600_down` sleeve logic
has a profitable 5m analogue. Signal: fire DOWN iff `close < ema_S AND close < ema_L`
(trend-continuation), fire UP iff `close > ema_S AND close > ema_L`.
EMA computed on Binance spot 1s closes, causal asof ≤ fire_us.

**Permutation-test validity note:** For single-direction filters (all-Down or all-Up),
the permutation test is invalid: the filter selects slugs in trend, so outcome_truth
has the same directional bias as the signal (~80% Down when filter=DOWN).
Permuting outcome labels preserves this base rate, yielding null WR ≈ observed WR → p→1.
Primary significance evidence = G4 IID bootstrap CI + G4b block-by-day CI + G2 walkforward.
G3 (permutation) is reported but flagged INVALID_BIASED for single-direction strategies.

# RIGOROUS RE-RUN (2026-06-01): bias-correct edge tests

The original permutation (Part 2 G3) shuffled outcome labels within the fired
set — an INVALID null. The DOWN filter conditions on the trend, so outcome_truth
is ~82% Down at the base rate; shuffling preserves that → null WR ≈ observed WR → p→1.
This section replaces it with three bias-free tests. **REALISTIC cost throughout**
(poly 0.07·p·(1-p) fee + $0.01 tx).

## 1. Look-ahead audit (causality proof)

- **Signal asof:** `get_close_and_emas()` (script ~L182) uses
  `idx = np.searchsorted(end_us, fire_us, side='right') - 1` → returns the 1s bar
  whose `time_period_end_us` ≤ `fire_us`. Strictly causal: no bar ending after the
  fire instant is visible.
- **EMA causality:** `compute_ema_panel()` (~L169) computes `ewm(span=N, adjust=False)`
  over the full ascending-time 1s close series. `ewm` is a trailing recursion — each
  point depends only on itself and prior points. The asof index then slices the EMA at
  the same ≤fire_us bar, so the EMA value used is a trailing-window EMA ending at/before
  the fire instant.
- **outcome_truth:** read ONLY in `fire_from_pool()` (~L*) at `f['won'] = direction ==
  outcome_truth`, AFTER every selection gate (EMA signal, traded-side ok, px band,
  spread). Never used in slug selection. Confirmed.

## 2. Survivorship / fill-selection audit

## 5. FINAL VERDICT (bias-free)

### (i) Is btc-15m off600 DOWN +$1.66/trade a REAL edge over the price?

**YES — real edge over the price.** All four bias-free gates pass on the FULL 34-day sample:
- WR−implied = +0.0727 (full-sample bootstrap CI [0.0378, 0.1055], CI_lo>0). Realized WR (0.8238) significantly beats the de-vigged entry price (0.7511) — this is genuine selection alpha, not favorite-bias.

  beats random same-price (±0.02) bets on non-selected slugs (null mean PnL = -0.5336, n_cand=465). Base-rate-controlled.
- Block bootstrap CI by UTC day = [0.4676, 2.8993] over 39 days — CI_lo>0 even with day-level serial correlation respected (22/34 days positive, median day +$1.45).
- OOS: train-60/test-40 split — test PnL = +1.9824/trade, test WR−implied = +0.0791, 2-day positive fraction = 0.875 (9/12 windows).

**CAVEAT (honest):** the OOS holdout is short (last 13 UTC days, n=166). Its point
estimates are positive and directionally consistent, but the OOS-only WR−implied
bootstrap CI_lo dips slightly negative (~−0.01) and the OOS-only block CI spans zero —
i.e. the edge is NOT independently significant on the 13-day holdout alone. The
FULL-sample evidence (34 days) is what clears the bar. Recommend ≥2–3 more weeks of
paper/live before sizing up. This is also a LATE-window (off=600/900s) sleeve: the live
0-placement is the cross-token spread gate, not the EMA gate — so capturing this edge
live requires the book to be tight enough at off=600, which it usually is NOT (per the
live ~319-eval/0-place behavior). The edge exists in the data; harvesting it live is
gated by fill availability.
