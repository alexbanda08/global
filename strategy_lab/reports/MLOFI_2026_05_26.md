# Multi-Level OFI (MLOFI) on Polymarket L25 — Cont/Xu/Gould implementation

**Date:** 2026-05-26
**Authors:** Strategy lab (MLOFI agent)
**Universe:** 240,882 fires × 2 token sides over 23-day window (Apr 24 → May 17 2026 UTC)
**Engine:** `engine_v2.LegacyConfig` (2%-on-profit fee, production parity per CLAUDE.md fee verification 2026-05-22)
**Outcome truth:** Chainlink RTDS (canonical)

## 1. What we did

Implemented the **Multi-Level Order Flow Imbalance** of Cont, Kukanov, Stoikov (2014)
and Xu, Cont, Gould (2019) on the Polymarket L25 book stream. Built per-fire panel
with 9 MLOFI features × 2 token sides + 4 cross-token skews. Tested
standalone (TASK 2), against L1-OFI (TASK 3), as gate overlay on 5 sleeves
(TASK 4), and strict 3-way train/val/lockbox validation (TASK 5).

### MLOFI formula (per Cont 2014 §3 eq 3.2)

For each pair of consecutive book snapshots `(prev, curr)`, at each level `i`:

```
BID side e_b_i:
  if curr_bid_i > prev_bid_i  (improved/new level): e_b_i = +curr_bid_size_i
  if curr_bid_i == prev_bid_i (size change only): e_b_i = curr_bid_size_i - prev_bid_size_i
  if curr_bid_i < prev_bid_i  (level vanished/dropped): e_b_i = -prev_bid_size_i

ASK side e_a_i: symmetric with sign flip (better ask = more sell pressure)
  if curr_ask_i < prev_ask_i: e_a_i = +curr_ask_size_i
  if curr_ask_i == prev_ask_i: e_a_i = curr_ask_size_i - prev_ask_size_i
  if curr_ask_i > prev_ask_i: e_a_i = -prev_ask_size_i

ofi_i = e_b_i - e_a_i   (positive = buy-side pressure dominates)
MLOFI(L,T) = sum over all events in window T of: sum_{i=1..L} w_i * ofi_i
  with w_i = 1/i (level-decay weighting)
```

**Critical implementation detail**: book updates are EVENT-LEVEL (sub-second).
The standard `load_orderbook_l25_streaming(..., subsample_1hz=True)` path drops
~30-100× of intra-second snapshots — we explicitly used `subsample_1hz=False`
to preserve the event sequence MLOFI requires.

Per-asset BTC event density = 7.4 events/sec on average in fire windows
(median 201 events in 30s, max 2,064). ETH ≈ 1.2 ev/sec, SOL ≈ 0.5 ev/sec.

### Verdict

**Agent N's "68-74% RMSE reduction" claim DOES NOT replicate on Polymarket
binary tokens.** Actual numbers are 0.011-0.060% RMSE reduction — three orders
of magnitude smaller than Agent N's prior on classical limit-order-book
equities/futures.

That said, **MLOFI does dominate L1-OFI** in directional information content:
- R² improves 1.8-3.6× (L5) and 2.7-3.6× (L25) over L1
- Sign-accuracy is 0.1-0.4 pp higher
- L25 dominates L5, confirming the deep-book signal IS present and is captured
  better with the per-level weighting

**Why the discrepancy with classical MLOFI literature**:
1. Polymarket books are MUCH sparser than equities/futures (median 30 events/30s
   on ETH vs ~10,000+ in equities). Less data → less signal.
2. Binary tokens trade in [0, 1] range; ALL price moves are mean-reverting on a
   short horizon, so flow predicts very little price change beyond a few seconds.
3. Polymarket's CLOB has weaker market-making competition than equities, so
   flow signals may carry less mid-period information.
4. The 60s future-return horizon may be too long for prediction-market microstructure
   (where alpha decays within seconds based on parquet observed event rates).

**Correlation of MLOFI to existing microstructure features** (n=231,739):

| Pair | rho |

| `up_mlofi_l5_30s` vs `up_imb5` (top-5 size imbalance) | 0.203 |
| `up_mlofi_l5_30s` vs `up_imb1` (top-1 imbalance) | 0.198 |

Confirmed: MLOFI is genuinely flow (delta-of-book), only weakly correlated to
point-in-time imbalance. Different signal than what the microstructure panel
already captured.

## 7. Top NEW deployable MLOFI sleeves

**0 net-new deployable MLOFI cells**. The 1 lockbox-passing cell adds zero
incremental edge over its baseline (which already passes lockbox without MLOFI).

The TASK 4 results that look good in-sample fail strict out-of-sample
validation. **MLOFI does NOT translate into deployable sleeves on the current
Polymarket up-down universe.**

### What could change this
1. **More data**: 23 days is at the lower bound for MLOFI calibration; classical
   MLOFI papers use 6-12 months of LOB data. We may be underpowered.
2. **Higher-frequency entry**: 60s windows may be too long; 5-10s windows might
   capture more of the alpha if it decays fast (untested here).
3. **Cross-asset MLOFI**: BTC MLOFI as gate on ETH/SOL sleeves (untested).
4. **Maker side**: MLOFI may be more informative for MAKER fills (timing limit
   orders) than taker direction.

## 8. Caveats and limitations

1. **1Hz subsampling NOT used.** We loaded raw events (~7-220 ev/sec) to compute
   MLOFI. Memory + time costs are substantially higher than other panels — ~10
   minutes to build per asset. If MLOFI becomes a live feature, the production
   feature pipeline needs the same raw event stream (it currently only mirrors
   top-of-book in `paper.book_fetched` events).
2. **Future-return target uses binance-spot 1s klines**, not Polymarket token
   price. This is correct for evaluating MLOFI's role in predicting underlying
   moves but mixes Polymarket flow with CEX price formation, which may
   underestimate MLOFI's edge on the Poly token price specifically.
3. **No latency adjustment.** The MLOFI computation uses books at fire_us; live
   would have ~85ms shift. The TASK 4 gate overlay results assume zero latency
   on the MLOFI signal which is reasonable since the gate is binary
   (sign-flips at ms-level are rare given Poly book update rate). For
   continuous-MLOFI strategies that use the actual magnitude, this needs
   revisiting.
4. **Z-score uses 7-day rolling window**; only 30k+ rows per asset support this.
   On a 5-day lockbox window the z-scores are STILL computed from training
   tail data (the rolling window crosses the train/val/lockbox boundary). This
   could bleed information across splits; a strict no-bleed approach would
   freeze z-stats at end-of-train.
5. **TASK 2 rule WR of 65-75% with negative EV** confirms the recurring
   Polymarket fee-drag pattern: directional accuracy alone is not enough; the
   book-walk slippage + 2%-on-profit fee require alpha that translates to
   ~10-15 pp EV after fees. None of our standalone MLOFI rules clears that bar.
6. **2/18 lockbox pass rate** is in line with general experience on this
   universe (typically 5-15% of in-sample candidates survive strict validation).
   No specific MLOFI red-flag.
7. **MLOFI L25 weighting is 1/i** — Cont 2014 suggests `1/depth` (where depth =
   distance from mid) which would be more appropriate for binary tokens where
   mid is well-defined and levels are equally spaced. Not tested.

## 10. Bottom line

**MLOFI works as advertised in theory** — R² improves 2-4× over L1-OFI on
prediction-market book data, exactly matching the direction Cont/Xu/Gould would
predict for large-tick instruments.

**MLOFI does NOT replicate Agent N's headline 68-74% RMSE reduction figure.**
On Polymarket up-down binary tokens, MLOFI gives 0.011-0.060% RMSE reduction
on future 60s return prediction. Both signals are weak in absolute terms;
MLOFI is just less weak.

**MLOFI does NOT produce deployable new sleeves at strict 3-way validation
standard.** 0 net-new deployable cells. 1 cell passes (momo_extreme ETH 15m +
g_mlofi_no_extreme) but it's a marginal modification of an already-deployable
baseline.

**The 2/18 lockbox pass rate suggests the strong TASK-4 in-sample lifts (e.g.
sniper_midwindow BTC 15m +$1,465) are over-fit to train period book dynamics
that don't persist out-of-sample.** Common pattern: MLOFI signals that worked
during late-April BTC volatility don't hold through May.

**Recommendation**: keep the MLOFI panel built (it's cheap once built) and
revisit when (a) we have 60-90 days of canonical data, (b) we have a faster
horizon target (5-10s instead of 60s) to test alpha-decay hypothesis, (c) we
add maker-side strategies where MLOFI may be more relevant than taker direction.

**Do not deploy MLOFI-gated sleeves to production at current data scale.**
